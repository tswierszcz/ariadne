# Supported capabilities and limitations

This document describes the current implementation of Ariadne. Future requirements live in [RECOMMENDATION](../RECOMMENDATION/README.MD); their presence does not mean a feature is available.

Last source review: 2026-11-05. Existing capability rows retain their previously recorded evidence; the ServiceLoader/JPMS row below reflects this session's tests and offline petclinic/WebGoat analyses.

## Reading the status

- **Implemented:** the specific behavior described is present; the label does not cover every variation of the mechanism.
- **Partial:** a defined subset exists, with material gaps listed.
- **Experimental:** available behavior undergoing qualification, with its conditions stated.
- **Not implemented:** the current pipeline does not provide that behavior.
- **Unassessed:** evidence is insufficient to state the current scope.

Implementation status, tested versions and evidence quality are separate. A completed design phase does not change product support.

| Capability | Status | Available scope and conditions | Limits and evidence |
|---|---|---|---|

[Input normalization](../internal/input/source.go), [dependency resolution](../internal/input/resolve.go). |
| Spring Boot fat JAR and WAR | Implemented | Recognizes the implemented BOOT-INF/WEB-INF layouts and extracts classes/libraries. | Extracted libraries replace the `-deps` source in the current CLI; no promise of arbitrary archive layouts. | EAR | Partial | Merges nested WAR application classes/libraries and treats top-level JARs as dependencies. | EJB JAR classes are not application roots; class/library names can collide and module isolation is not modeled. [Input](../internal/input/source.go). |
| Maven component identity | Partial | Embedded `pom.properties`, then dependency-list filename fallback; unidentified JARs are reported. **Component inventory (CVE:F1a):** every jar read becomes an artifact (SHA-256, size, a location stable across runs — `app:<input>`, `deps:<file>`, or `app:<input>!/BOOT-INF/lib/…`/`WEB-INF/lib/…`/`module.war!/WEB-INF/lib/…` for jars extracted from the application archive) with one component instance (identity, detection `pom.properties`/`deps-list`/`webjar`/`unidentified`, identity evidence, selected classes and packages); further `pom.properties` in the same jar are listed as embedded candidates; every class present in several jars is a conflict with the selected and the non-selected copy, content-equal or not, under the stated classpath order (first copy wins). Identifiers are hashes of content and location, never of temp paths. Shown in the report's "Components" section; verdicts and `results.json` are unchanged. Measured offline: petclinic 88 artifacts, 31 conflicts (all identical copies); WebGoat 127 artifacts, 242 conflicts (**163 with different content**); petclinic as a Spring Boot fat jar: 76 artifacts with `BOOT-INF/lib` locations, identifiers identical across two runs. Verified by `internal/component` tests (stable identifiers for a classes directory and a fat jar, two instances of one GAV, embedded candidates, conflicts, unidentified jar) with mutation checks. **Embedded components without relocation (CVE:F6a, 2026-11-06):** every further `pom.properties` in a dependency jar is a candidate. One of the host's own project (same version; the same group or one nested in the other, e.g. `org.ehcache.modules:*` in `org.ehcache:ehcache`) is a *module* — part of the host, no lookup. Any other is a *library* candidate, checked against the jar of exactly that version from Maven Central (`ARIADNE_MAVEN_CENTRAL` overrides the root; cached as pinned — Central never changes a release; offline/snapshot replay read it from the cache): class entries are compared by name, then by bytes (CRC-32 + size) or by a serialization-independent class fingerprint (`classfile.Fingerprint`: header, fields, methods, instructions with constant-pool operands resolved to what they name, `ldc_w`/`goto_w` folded, branch targets as instruction indexes) — shading tools rewrite class files even without renaming them (jnr-ffi in jruby-core: 0 of 656 byte-identical, 644 by fingerprint; the other 12 reference a relocated ASM). Outcome: `confirmed` (≥ 50% of the reference classes present and ≥ 90% of those the same class) → its own instance (detection `embedded`, location `<jar location>!/META-INF/maven/<g>/<a>`, `embedded_in` the host) owning those classes (class counts, packages and class conflicts are per class), and its own OSV lookup, so findings are per embedded instance; `content_differs`, `partial` (minimized copy), `classes_absent` (stale metadata, or a relocated copy — CVE:F7), `reference_unavailable` → no instance, no lookup, listed in v2 `coverage.embedded_candidates` and the report's "Embedded component candidates" table as a coverage gap. Two copies in two versions are two instances. Measured (CVE:F0 inputs, `-profile spring`): petclinic — `ehcache-3.9.2`: 5 modules, `org.ehcache:sizeof:0.4.0` and `org.terracotta:terracotta-utilities-tools:0.0.6` confirmed (66/66 and 22/22 classes), `offheap-store`/`statistics` classes absent (relocated under `org.ehcache.shadow`), byte-buddy's `byte-buddy-dep` a module; WebGoat — `com.github.jnr:jnr-ffi:2.2.1` in `jruby-core-9.2.14.0` confirmed (656 classes), `jitescript` absent (relocated). None of the three confirmed versions has an OSV advisory, so no finding changed (same OSV data before/after); v2 byte-identical over two runs. Tests: `internal/component/embedded_test.go`, `internal/classfile/fingerprint_test.go`, `internal/reach/f6_test.go` (an advisory against an embedded library gets a REACHABLE finding on the embedded instance), with mutation checks. **Explicit relocation (CVE:F7a, 2026-11-06):** relocation rules come from the host jar's own `META-INF/maven/<g>/<a>/pom.xml` (every maven-shade-plugin `<relocation>` of every execution/profile; placeholders and wildcards skipped with a note; other plugins ignored) and from `-embedded-components` (YAML, version 1, per jar SHA-256: components by GAV — also without a `pom.properties` — and `from`/`to` package relocations; strict schema; an entry for an unknown hash or a named jar with another hash is reported in `coverage.embedded_declaration_issues` and ignored). Rules apply to the whole jar (`internal/relocate`: package-boundary prefixes, longest wins, conflicting rules rejected → `relocation_conflict`); reference classes are looked up under their relocated names and compared through the inverse relocation (`classfile.FingerprintWith` rewrites names in the header, descriptors, constant-pool references and class-name string literals); a class already attributed to another confirmed candidate is a `collision`. A confirmed relocated instance records its own rules with their source (report: original → in-jar names; v2 `relocations[]`), and the engine matches each mapped selector also rewritten by them (names and descriptors). Measured (`-embedded-components testdata/embedded/petclinic-ehcache.yaml` on petclinic): `org.terracotta:offheap-store:2.5.1` (167/167) and `org.terracotta:statistics:2.1` (130/130) confirmed under `org.ehcache.shadow.org.terracotta.*`; WebGoat with no declaration: jruby-core's pom.xml gives 2 maven-shade rules, `me.qmx.jitescript:jitescript:0.4.1` confirmed (9/9) under `org.jruby.me.qmx.jitescript`, jnr-ffi now 656/656 identical (its 12 references to the relocated ASM map back). No advisory exists for these versions: verdicts unchanged (same OSV data before/after); v2 byte-identical over two runs. Tests: `internal/relocate`, `internal/component/relocation_test.go`, `internal/reach/f6_test.go` (`TestRelocatedInstanceFinding`), with mutation checks. | Candidates come only from `pom.properties` or a declaration (no SBOM — CVE:F6b); relocation must be explicit — an unknown relocation is not discovered (planned as a separate experimental stage); shade `<includes>`/`<excludes>` and `rawString` are not modeled (the classes decide); a rule from the pom applies to the whole jar even if it came from a profile not used for this build; diff-mapping bytecode verification (CVE:F5b) and LLM grounding look up original names, so a relocated class reads as `class_missing` there; only the declared version is checked (no candidate-version search: a copy of another version is `content_differs`, a gap); a reference must be on Maven Central under the declared GAV; the thresholds are fixed; classes of a not-confirmed candidate stay with the host; the module rule trusts group/version (a separately versioned library of the same organization is a library candidate, e.g. `org.ehcache:sizeof`); relocation is CVE:F7. Before CVE:F6a: one instance per jar. Findings are per advisory × instance since CVE:F1b (report, and `-json-format v2`); a conflict that shadows the affected instance's copy gives `CLASSPATH_CONFLICT`. [Resolver](../internal/input/resolve.go), [component inventory](../internal/component/component.go). |
| Shaded/relocated components | Not implemented | Multiple POM entries may be detected as metadata candidates. | No complete component-to-class ownership or relocation model. [Resolver](../internal/input/resolve.go), [planned CVE work](../RECOMMENDATION/CVE.MD). |

| Reflection (Class/Method/Constructor) | Partial | REFLECTION R0+R1 (first slice, new): `internal/dataflow` recognizes a `Class.forName(String)`/`forName(String, boolean, ClassLoader)` call whose class-name argument is a provable string literal, and resolves it directly to the same `valueflow.KindConst`/`"java.lang.Class"` shape a `Foo.class` literal already produces — a deliberate R0 design decision to **reuse** the existing Kind rather than add a new one, since `Class.forName("X")` and `X.class` are the same fact ("the Class object named by this FQCN") reached two different ways; any existing consumer of a Class-typed `KindConst` (e.g. SERVICE_LOADING S1's own `ServiceLoader.load(Class)` argument reading) benefits immediately with no changes of its own. A second, independent gap had to close first: D2 never tracked `int` literals at all (`iconst_*`/`bipush`/`sipush`/`ldc` Integer — declared out of scope, "stałe napisowe/klasowe" only), so `aastore`'s own literal index was unreadable; a narrow `ConstKindInt` was added, scoped only to int literals (no arithmetic). Verified: 7 new unit tests across `internal/classfile`/`internal/dataflow` (one-element array, two-element array confirming the shared-pointer mutation survives more than one `dup`+`aastore`, a zero-length array, a non-literal name not fabricated) — `go build`/`go vet`/`go test`/`go test -race` all green, including against both control apps' full hierarchies (29k/40k classes) with no panic and byte-identical `results.json` across two offline runs on each. Measured: **0 effect** on petclinic/WebGoat — neither app's own source calls `Class#getMethod`/`getDeclaredMethod` (confirmed: the only `getMethod()` hits in either app's source are an unrelated HTTP-request API, not `java.lang.Class`'s). REFLECTION R2 (new): the first slice that produces a real call-graph edge, not just a value-domain fact. `internal/reflectinvoke` finds every `java.lang.reflect.Method#invoke(Object, Object...)` call site (`sites.go`), resolves its Method receiver back to an R1 `KindReflectiveMethod` fact where the data-flow value is known (`resolve.go` — a receiver that is a parameter, a field read, or any other unresolved value is correctly left unresolved, not guessed), then (`edges.go`) resolves dispatch on the invocation's own first argument: the target's concrete allocation type when the value flow proves one (`hierarchy.ResolveExact`, exact descriptor), the `Class` the reflective lookup was performed on otherwise (`hierarchy.ResolveByParams`, new — matches by parameter types alone since a `getMethod` call never proves a return type, JVM lookup order, declared via the new exported `classfile.ParamDescriptors`/`ClassInfo.MethodByNameAndParams`). Every resolved declaring class gets an edge to *every* overload of the resolved method name on it (`BasisReflection`, new `EdgeBasis`, the same "may run" reasoning as `BasisCallback`/`BasisMethodHandle` — a caught `ReflectiveOperationException` or a dead branch can still mean `invoke` never actually runs). A literal argument array whose length provably mismatches the resolved Method's parameter count, or a parameter type that isn't a plain class literal, produces a reported **Gap**, never a fabricated edge. Verified: new unit tests across `internal/reflectinvoke` (site discovery, receiver resolution, edge construction including the gap cases) and `internal/hierarchy` (`resolve_params_test.go`, `ResolveByParams`/`MethodByNameAndParams`) — `go build`/`go vet`/`go test`/`go test -race` all green. Measured on real petclinic/WebGoat: **non-zero**, unlike R0/R1 — petclinic: 619 `Method#invoke` call sites found, 5 resolved to a real edge (`AprLifecycleListener→SSL#randSet/initialize`, `SessionRemote→Engine#getInstance`, two `HCANNHelper` sites into Hibernate's reflection abstraction layer), moving the `-profile spring` run from 3/59/29/51/6 to **3/62/26/51/6** (REACHABLE/FRAMEWORK/NOT_REACHABLE/UNKNOWN/NOT_APPLICABLE — 3 cases moved NOT_REACHABLE→FRAMEWORK). WebGoat: 628 call sites found, 4 resolved to 3 edges, moving the same `-profile spring` run from 40/43/21/56/0 to **42/44/18/56/0**. Two offline runs on each app give byte-identical `results.json`. REFLECTION R2's own second half (new): `Constructor#newInstance` → real call-graph edges to the constructor's allocation, mirroring the above but exact rather than dispatch-based. `internal/dataflow` gains `reflectiveConstructorValue`/`valueflow.KindReflectiveConstructor` (new, `ReflectiveMethodValue`'s own counterpart, reusing R1's existing `KindArray` literal-tracking machinery — no new array model needed, since `getConstructor`/`getDeclaredConstructor` take the same `Class[]` shape with no name argument). `internal/reflectinvoke` gains `newinstance_sites.go`/`newinstance_resolve.go`/`newinstance_edges.go`, mirroring the `Method#invoke` three-stage split. ## Interpretation and maintenance

`NOT_REACHABLE` means no path was found under the implemented model and chosen roots. It is not a guarantee that the application is safe. `NOT_APPLICABLE` identifies the implemented WebJar-only case; browser vulnerabilities may still matter. A profile match, configured registration, static path, LLM opinion and runtime observation are different evidence types.

**Results contract (CVE:F0, 2026-11-05).** The meaning of every result axis, state and reason code is fixed in [RESULTS_CONTRACT.MD](RESULTS_CONTRACT.MD); this is a contract, not a new feature. Two v1 behaviors it documents: (1) a `NOT_REACHABLE` row also covers "no mapped method exists in the analyzed graph" — measured on the baseline as 7 of 26 (petclinic) and 6 of 18 (WebGoat) `NOT_REACHABLE` rows, all diff-derived mappings of methods absent under those names in the analyzed version ([estimate](../testdata/baseline/VERDICT_CHANGE_ESTIMATE.MD)); CVE:F1b reports them as `UNKNOWN`/`METHOD_NOT_FOUND`; (2) explicit model gaps were reported only globally. The 39 embedded manual mappings are entry points (38) or a sink (1), none a complete mapping of the vulnerable code ([audit](../testdata/cve-control/MANUAL_MAPPING_AUDIT.MD)). A control set ([testdata/cve-control](../testdata/cve-control/README.MD)) and a reproducible baseline ([testdata/baseline](../testdata/baseline/README.MD), responses exported outside the repository by `scripts/cve-baseline.sh`) are the reference data for CVE:F1+. **Reason codes and per-instance findings (CVE:F1b, 2026-11-05).** Results carry stable `reasons`; `METHOD_NOT_FOUND` and `CLASSPATH_CONFLICT` make a row `UNKNOWN`; `MAPPING_PARTIAL`/`MAPPING_ENTRYPOINT_ONLY` qualify a verdict without changing it. An advisory is evaluated per affected component instance and aggregated (a positive path wins; an unresolved instance is never hidden under `NOT_REACHABLE`); a path never runs through another jar's copy of a class the affected instance also holds. The model-gap rule (contract §4) is **report-only**: a `NOT_REACHABLE` row with reachable unresolved sites that could dispatch into the affected component keeps its verdict and adds `MODEL_INCOMPLETE` plus counts by kind — measured, it applies to every `NOT_REACHABLE` row of both reference apps (376/456 reachable sites have no bounded candidate set; bounded sites alone still cover 18/19 and 11/12), so it cannot yet separate cases. **v2 results (CVE:F1c, 2026-11-05):** `-json-format v2` writes components, findings per advisory × instance, coverage and an inputs reference ([contract §5](RESULTS_CONTRACT.MD)); v1 remains the default, byte-identical to F1b on the reference apps, and every run checks that the v2 findings aggregate to the v1 verdicts. Not yet in v2: data snapshot (CVE:F3), version ranges/`not_affected` (CVE:F4), `not_assessed` findings (CVE:F8).
