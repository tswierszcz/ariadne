# Supported capabilities and limitations

This document describes the current implementation of Ariadne. Future requirements live in [RECOMMENDATION](../RECOMMENDATION/README.MD); their presence does not mean a feature is available.

Last source review: 2026-11-05. Existing capability rows retain their previously recorded evidence; the ServiceLoader/JPMS row below reflects this session's tests and offline petclinic/WebGoat analyses.

## Reading the status

- **Implemented:** the specific behavior described is present; the label does not cover every variation of the mechanism.
- **Partial:** a defined subset exists, with material gaps listed.
- **Experimental:** available behavior undergoing qualification, with its conditions stated.
- **Not implemented:** the current pipeline does not provide that behavior.
- **Unassessed:** evidence is insufficient to state the current scope.

Implementation status, tested versions and evidence quality are separate. A completed design phase does not change product support.

|---|---|---|---|

[Input normalization](../internal/input/source.go), [dependency resolution](../internal/input/resolve.go). |

| EAR | Partial | Merges nested WAR application classes/libraries and treats top-level JARs as dependencies. | EJB JAR classes are not application roots; class/library names can collide and module isolation is not modeled. [Input](../internal/input/source.go). |
| Maven component identity | Partial | Embedded `pom.properties`, then dependency-list filename fallback; unidentified JARs are reported. When no `pom.properties` in a jar matches its file name and the dependency list names that exact file, the list wins (2026-11-07: groovy 2.4.x, whose only `pom.properties` is its repackaged commons-cli's, was queried as commons-cli 1.2). **Component inventory (CVE:F1a):** every jar read becomes an artifact (SHA-256, size, a location stable across runs — `app:<input>`, `deps:<file>`, or `app:<input>!/BOOT-INF/lib/…`/`WEB-INF/lib/…`/`module.war!/WEB-INF/lib/…` for jars extracted from the application archive) with one component instance (identity, detection `pom.properties`/`deps-list`/`webjar`/`unidentified`, identity evidence, selected classes and packages); further `pom.properties` in the same jar are listed as embedded candidates; every class present in several jars is a conflict with the selected and the non-selected copy, content-equal or not, under the stated classpath order (first copy wins). Identifiers are hashes of content and location, never of temp paths. Shown in the report's "Components" section; verdicts and `results.json` are unchanged. Measured offline: petclinic 88 artifacts, 31 conflicts (all identical copies); WebGoat 127 artifacts, 242 conflicts (**163 with different content**); petclinic as a Spring Boot fat jar: 76 artifacts with `BOOT-INF/lib` locations, identifiers identical across two runs. Verified by `internal/component` tests (stable identifiers for a classes directory and a fat jar, two instances of one GAV, embedded candidates, conflicts, unidentified jar) with mutation checks. **Embedded components without relocation (CVE:F6a, 2026-11-06):** every further `pom.properties` in a dependency jar is a candidate. One of the host's own project (same version; the same group or one nested in the other, e.g. `org.ehcache.modules:*` in `org.ehcache:ehcache`) is a *module* — part of the host, no lookup. Any other is a *library* candidate, checked against the jar of exactly that version from Maven Central (`ARIADNE_MAVEN_CENTRAL` overrides the root; cached as pinned — Central never changes a release; offline/snapshot replay read it from the cache): class entries are compared by name, then by bytes (CRC-32 + size) or by a serialization-independent class fingerprint (`classfile.Fingerprint`: header, fields, methods, instructions with constant-pool operands resolved to what they name, `ldc_w`/`goto_w` folded, branch targets as instruction indexes) — shading tools rewrite class files even without renaming them (jnr-ffi in jruby-core: 0 of 656 byte-identical, 644 by fingerprint; the other 12 reference a relocated ASM). Outcome: `confirmed` (≥ 50% of the reference classes present and ≥ 90% of those the same class) → its own instance (detection `embedded`, location `<jar location>!/META-INF/maven/<g>/<a>`, `embedded_in` the host) owning those classes (class counts, packages and class conflicts are per class), and its own OSV lookup, so findings are per embedded instance; `content_differs`, `partial` (minimized copy), `classes_absent` (stale metadata, or a relocated copy — CVE:F7), `reference_unavailable` → no instance, no lookup, listed in v2 `coverage.embedded_candidates` and the report's "Embedded component candidates" table as a coverage gap. Two copies in two versions are two instances. Measured (CVE:F0 inputs, `-profile spring`): petclinic — `ehcache-3.9.2`: 5 modules, `org.ehcache:sizeof:0.4.0` and `org.terracotta:terracotta-utilities-tools:0.0.6` confirmed (66/66 and 22/22 classes), `offheap-store`/`statistics` classes absent (relocated under `org.ehcache.shadow`), byte-buddy's `byte-buddy-dep` a module; WebGoat — `com.github.jnr:jnr-ffi:2.2.1` in `jruby-core-9.2.14.0` confirmed (656 classes), `jitescript` absent (relocated). None of the three confirmed versions has an OSV advisory, so no finding changed (same OSV data before/after); v2 byte-identical over two runs. Tests: `internal/component/embedded_test.go`, `internal/classfile/fingerprint_test.go`, `internal/reach/f6_test.go` (an advisory against an embedded library gets a REACHABLE finding on the embedded instance), with mutation checks. **Explicit relocation (CVE:F7a, 2026-11-06):** relocation rules come from the host jar's own `META-INF/maven/<g>/<a>/pom.xml` (every maven-shade-plugin `<relocation>` of every execution/profile; placeholders and wildcards skipped with a note; other plugins ignored) and from `-embedded-components` (YAML, version 1, per jar SHA-256: components by GAV — also without a `pom.properties` — and `from`/`to` package relocations; strict schema; an entry for an unknown hash or a named jar with another hash is reported in `coverage.embedded_declaration_issues` and ignored). Rules apply to the whole jar (`internal/relocate`: package-boundary prefixes, longest wins, conflicting rules rejected → `relocation_conflict`); reference classes are looked up under their relocated names and compared through the inverse relocation (`classfile.FingerprintWith` rewrites names in the header, descriptors, constant-pool references and class-name string literals); a class already attributed to another confirmed candidate is a `collision`. A confirmed relocated instance records its own rules with their source (report: original → in-jar names; v2 `relocations[]`), and the engine matches each mapped selector also rewritten by them (names and descriptors). Measured (`-embedded-components testdata/embedded/petclinic-ehcache.yaml` on petclinic): `org.terracotta:offheap-store:2.5.1` (167/167) and `org.terracotta:statistics:2.1` (130/130) confirmed under `org.ehcache.shadow.org.terracotta.*`; WebGoat with no declaration: jruby-core's pom.xml gives 2 maven-shade rules, `me.qmx.jitescript:jitescript:0.4.1` confirmed (9/9) under `org.jruby.me.qmx.jitescript`, jnr-ffi now 656/656 identical (its 12 references to the relocated ASM map back). No advisory exists for these versions: verdicts unchanged (same OSV data before/after); v2 byte-identical over two runs. Tests: `internal/relocate`, `internal/component/relocation_test.go`, `internal/reach/f6_test.go` (`TestRelocatedInstanceFinding`), with mutation checks. **Candidate versions, build configuration and SBOM (CVE:F6b, 2026-11-06):** (1) *Version search* — when the declared version does not fit the classes (`content_differs`) or no version is known, the other published versions of the same group:artifact are compared the same way (Central `maven-metadata.xml`, cached as mutable data; SNAPSHOTs dropped; Maven ordering): the up to 8 nearest the declared version, or — with none declared — all of them only when at most 8 are published (otherwise not searched, `version_unknown`). Exactly one fitting version → `confirmed` with that version, read from the classes (v2 `version`, the reason says the declared one did not fit); several → `version_candidates`: an instance with the bounded candidate set (`gav` `g:a:{v1,v2}`, identity `version_candidates`), OSV queried for every candidate, its findings carry `VERSION_CANDIDATES` and v2 applicability `undetermined` unless every candidate is affected; a versioned mapping is used only when every candidate selects the same variant (else `VERSION_UNKNOWN`); none fits → `version_unknown`, no instance, a gap. A `partial`, `classes_absent` or `reference_unavailable` candidate is not searched. Every compared version is listed (`versions_checked[]`, `version_search`). (2) *Build configuration* — the host's embedded `pom.xml`: maven-shade-plugin `<artifactSet><includes>` (glob patterns; `<excludes>` honored) ∩ the pom's `<dependencies>` (compile/runtime, not optional, no classifier), followed transitively through the dependencies' Central poms (depth ≤ 4, same include filter); `${…}` versions resolved from the pom's properties, its parent chain (fetched from Central, pinned) and `dependencyManagement`; ISO-8859-1 poms are read. Candidates (`source: build-config`, the dependency chain in `source_detail`; instance location `<host>!/build-config/<g>/<a>`) are verified by their classes like any other; a shade configuration without includes ("shade everything") yields none, with a note. (3) *SBOM* — `-sbom FILE`, CycloneDX JSON 1.4–1.6 only: a component whose SHA-256 equals an analyzed dependency jar's is tied to that jar (identity evidence `sbom` on it; a disagreeing GAV, or a GAV for an unidentified jar, is reported in `coverage.sbom.issues` and never replaces the identity read from the jar); Maven components (`pkg:maven/…` purl, no classifier) nested in a tied component become candidates (`source: sbom`), verified by their classes; anything else in the SBOM (untied components, the `dependencies` graph) is counted and not used. The SBOM file is a snapshot input. Measured (`-profile spring`, `-json-format v2`, F7a vs F6b, same cache): WebGoat — 5 build-config candidates from jruby-core's pom (`asm.version` = 9.0 from `org.jruby:jruby-parent:9.2.14.0`; `asm-tree`/`asm-analysis` through `asm-commons`' pom): `org.ow2.asm:asm`, `asm-commons`, `asm-util`, `asm-tree`, `asm-analysis` 9.0 confirmed under `org.jruby.org.objectweb` (37+27+24+38+14 = all 140 relocated ASM classes, all identical); with the control SBOM `testdata/sbom/webgoat-jruby.cdx.json` (jruby-core tied by hash; `asm-util` deliberately declared 9.1): 9.1 does not fit (18/24), of 8 neighbouring releases 9.0-beta and 9.0 both fit 24/24 → `version_candidates {9.0-beta, 9.0}`, not a pick; 1 untied component not used. Petclinic — unchanged (byte-buddy's shade configuration has no includes: noted). No ASM 9.0/9.0-beta advisory exists in OSV: advisories, findings and verdicts identical before/after on both apps (petclinic 153/160, WebGoat 164/172); v2 byte-identical over two offline runs. Tests: `internal/component/f6b_test.go` (version from classes, candidates, none fits, declared fits without search, partial not searched, window, version list order; build-config with parent property, dependencyManagement, transitive, excluded/test/optional/unincluded; no includes; unresolved version; SBOM tie/nesting/untied/disagreement; rejected SBOMs; purl parsing), `internal/reach/f6_test.go` (`TestVersionCandidatesFinding`, `TestVersionCandidatesVariants`), `internal/resultsv2/f6b_test.go`. | Candidates come from `pom.properties`, a declaration, the jar's own shade `artifactSet` includes, or a hash-tied CycloneDX SBOM (no SPDX; no other build tools' configuration — Gradle Shadow leaves none in the jar); a version search compares at most 8 published versions and needs Central's version list (offline without it: not searched); a candidate set means the classes cannot tell the versions apart, not that both are present; relocation must be explicit — an unknown relocation is not discovered (planned as a separate experimental stage); shade `<includes>`/`<excludes>` and `rawString` are not modeled (the classes decide); a rule from the pom applies to the whole jar even if it came from a profile not used for this build; diff-mapping bytecode verification (CVE:F5b) and LLM grounding look up original names, so a relocated class reads as `class_missing` there; a reference must be on Maven Central under the candidate's GAV; the thresholds are fixed; classes of a not-confirmed candidate stay with the host; the module rule trusts group/version (a separately versioned library of the same organization is a library candidate, e.g. `org.ehcache:sizeof`); relocation is CVE:F7. Before CVE:F6a: one instance per jar. Findings are per advisory × instance since CVE:F1b (report, and `-json-format v2`); a conflict that shadows the affected instance's copy gives `CLASSPATH_CONFLICT`. [Resolver](../internal/input/resolve.go), [component inventory](../internal/component/component.go). |
| Shaded/relocated components | Partial | Embedded copies named by `pom.properties`, `-embedded-components`, the jar's maven-shade `artifactSet` includes or a hash-tied CycloneDX SBOM, confirmed by their classes, with explicit relocation and a bounded candidate-version search — see "Maven component identity" (CVE:F6a, F6b, F7a). | Unknown relocations are not discovered; a copy no source names is not found; see the limitations of "Maven component identity". The model does not generate runtime classes, invalidate dependent results after model changes, or implement RTA/points-to. Verified with `go test ./...`, `go vet ./...` and offline app runs (final verification is recorded in the implementation status). | Multi-release target selection | Partial | `-target-java N` (JVM_GRAPH G4) selects, for a jar whose manifest declares `Multi-Release: true`, the highest `META-INF/versions/<V>/...` variant with `V <= N` per class, falling back to the base entry; without the flag, every jar's base classes are read regardless of any `META-INF/versions/` present — the documented fallback, not a guess from the highest bytecode version seen. Verified on real petclinic/WebGoat: `-target-java 17` activates 15/21 real variants respectively (8 genuinely multi-release dependency jars identified in petclinic alone, e.g. `log4j-api`, `byte-buddy`, `h2`), with no change to either app's CVE statuses in the current baseline. | A jar not declaring `Multi-Release: true` never treats `META-INF/versions/` as active, even with a target set (correct per the JAR File Specification). Initialization order/timing and the CVE F8a target-description contract are out of this phase's scope ("pełny adapter podatności JDK nie jest wymagany"). Consolidated reference for the "ServiceLoader and JPMS service models" row above

## Interpretation and maintenance

`NOT_REACHABLE` means no path was found under the implemented model and chosen roots. It is not a guarantee that the application is safe. `NOT_APPLICABLE` identifies the implemented WebJar-only case; browser vulnerabilities may still matter. A profile match, configured registration, static path, LLM opinion and runtime observation are different evidence types.

**One gap vocabulary (ROADMAP B0 b0-3, 2026-11-13).** Every analyzer's gap codes (model-gap sites, created-type catalog, SAM calls, B3 coordinator, trace causes) map to one mechanism (`internal/gaps`, contract "Gap vocabulary", kept identical by `TestVocabularyDocumented`; `TestEveryProducerCodeMapped` fails on an unmapped code); report "Model gaps by mechanism", v2 `coverage.gaps`, `findings[].gaps`. No rule change: only `site` gaps feed `MODEL_INCOMPLETE` — unresolved SAM calls and skipped `java.*`/`javax.*` receivers are reported, not applied to findings. v1 byte-identical on petclinic/WebGoat/JPetStore. **Gap-rule probe (ROADMAP B0 b0-4, 2026-11-14).** Report-only measurement per `NOT_REACHABLE` finding of four rule variants (instance-bounded gaps only; + unresolved lambda calls with a lambda created in the instance; + calls on `java.*`/`javax.*` types whose skipped CHA expansion lands in the instance, with and without `Object` methods): v2 `findings[].gap_probe`, `coverage.gap_probe`, report "Gap-rule probe". petclinic/WebGoat/JPetStore: current 18/18/15 of 18/18/15, scoped 17/15/14, +lambda 17/16/14, +skipped 18/18/15 — adding SAM or skipped-receiver gaps changes no mark, and skipped receivers reach every instance, so the rule is unchanged. v1 byte-identical. **Path evidence (ROADMAP B0/B1, 2026-11-13).** Every step of a reported path carries its edges (kind, basis, call-site offsets) and a character — `jvm_rule`, `library_model`, `input_declaration`, `heuristic` (CHA only) — in v2 `findings[].path_edges`/`character` and the report's path; since `b0-2` the reported path avoids CHA-only steps whenever possible (so `heuristic` = reachable only through a CHA expansion: petclinic 99/109, WebGoat 81/137, JPetStore 16/16 positive findings; no verdict changed, +0.1–0.4 s). Unmapped advisories carry `MAPPING_MISSING`. Verified: `internal/reach` tests (overload fixture, every basis), petclinic/WebGoat/JPetStore v1 identical to the previous build apart from the new code (no verdict changed). **Results contract (CVE:F0, 2026-11-05).** The meaning of every result axis, state and reason code is fixed in [RESULTS_CONTRACT.MD](RESULTS_CONTRACT.MD); this is a contract, not a new feature. Two v1 behaviors it documents: (1) a `NOT_REACHABLE` row also covers "no mapped method exists in the analyzed graph" — measured on the baseline as 7 of 26 (petclinic) and 6 of 18 (WebGoat) `NOT_REACHABLE` rows, all diff-derived mappings of methods absent under those names in the analyzed version ([estimate](../testdata/baseline/VERDICT_CHANGE_ESTIMATE.MD)); CVE:F1b reports them as `UNKNOWN`/`METHOD_NOT_FOUND`; (2) explicit model gaps were reported only globally. The 39 embedded manual mappings are entry points (38) or a sink (1), none a complete mapping of the vulnerable code ([audit](../testdata/cve-control/MANUAL_MAPPING_AUDIT.MD)); since 2026-11-10 there are 46: seven more sinks for HSQLDB CVE-2022-41853 and six log4j 1.2 advisories (SocketServer, JMSAppender, JMSSink, JDBCAppender, Chainsaw), versioned over the releases checked in the bytecode (HSQLDB 2.0.0–2.7.0, log4j 1.2.8–1.2.17; same audit). Since 2026-11-13 there are 68: 22 entries for advisories with neither a fix commit nor a class name (SnakeYAML DoS, Spring MVC static resources/SSE/script templates, SpEL, Spring log injection, Thymeleaf), each from a hand-read release diff and checked by name over a span of releases (same audit). A control set ([testdata/cve-control](../testdata/cve-control/README.MD)) and a reproducible baseline ([testdata/baseline](../testdata/baseline/README.MD), responses exported outside the repository by `scripts/cve-baseline.sh`) are the reference data for CVE:F1+. **Reason codes and per-instance findings (CVE:F1b, 2026-11-05).** Results carry stable `reasons`; `METHOD_NOT_FOUND` and `CLASSPATH_CONFLICT` make a row `UNKNOWN`; `MAPPING_PARTIAL`/`MAPPING_ENTRYPOINT_ONLY` qualify a verdict without changing it. An advisory is evaluated per affected component instance and aggregated (a positive path wins; an unresolved instance is never hidden under `NOT_REACHABLE`); a path never runs through another jar's copy of a class the affected instance also holds. The model-gap rule (contract §4) is **report-only**: a `NOT_REACHABLE` row with reachable unresolved sites that could dispatch into the affected component keeps its verdict and adds `MODEL_INCOMPLETE` plus counts by kind — measured, it applies to every `NOT_REACHABLE` row of both reference apps (376/456 reachable sites have no bounded candidate set; bounded sites alone still cover 18/19 and 11/12), so it cannot yet separate cases. **v2 results (CVE:F1c, 2026-11-05):** `-json-format v2` writes components, findings per advisory × instance, coverage and an inputs reference ([contract §5](RESULTS_CONTRACT.MD)); v1 remains the default, byte-identical to F1b on the reference apps, and every run checks that the v2 findings aggregate to the v1 verdicts. Not yet in v2: data snapshot (CVE:F3), version ranges/`not_affected` (CVE:F4), `not_assessed` findings (CVE:F8).
